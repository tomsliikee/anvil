# Anvil Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Anvil, a Visual-Studio-compatible C# IDE for Linux (Rust, GTK 4, libadwaita, GtkSourceView 5, Flatpak, Insights Mono), whose files Visual Studio 2026 opens unchanged.

**Architecture:** A Rust workspace: `anvil-core` holds every format, model and rule as pure, host-tested code; `anvil-lsp`, `anvil-dap`, `anvil-ai` and `anvil-git` are GTK-free async clients for Roslyn, netcoredbg, Ollama and git; `anvil` is the GTK app, built in the GNOME 51 SDK, that talks to them through a Tokio runtime and channels (Atlas' `runtime.rs` pattern). Everything external (dotnet, Roslyn, netcoredbg, git, the user's program) runs on the host via `flatpak-spawn --host`.

**Tech Stack:** Rust 2024, GTK 4.24 / libadwaita 1.10 / GtkSourceView 5.22 (GNOME 51 SDK), VTE (built in the manifest), Tokio, tree-sitter-c-sharp, quick-xml, lsp-types, reqwest, zip, gettext.

**Spec:** `docs/superpowers/specs/2026-11-18-anvil-design.md` (approved 2026-11-18; its decisions are not reopened here).

## Global Constraints

- App ID `io.github.tomsliikee.Anvil`, licence MIT, GNOME 51 runtime, Rust stable SDK extension (as Atlas).
- No dependency beyond the list Thomas approved (section "Dependencies"); a new one needs his yes first.
- Every file Anvil changes keeps its BOM and line endings; unchanged files are never rewritten; only the changed range is replaced.
- New files: VS 2026 item template text, UTF-8 with BOM, CRLF, not StyleCop-cleaned.
- `.cd` written as VS writes it: UTF-8 BOM, CRLF, two-space indent, unchanged diagram → identical bytes.
- Anvil-only state goes to `.vs/anvil/` in the solution folder, never into the project folder.
- Hand-in ZIP: `<Solution>.zip` without `bin/`, `obj/`, `.vs/` and without what `.gitignore` excludes.
- Design: Insights Mono tokens only (no colour literal outside `tokens.json`); Inter UI, Cascadia Mono code (Geist Mono in the original plan), Geist Serif for statements; cards radius 22 on `bg`, toolbar `bar` radius 30, one `solid` button (Start); no emoji, no status dots, no glows; Adwaita symbolic icons only.
- Colour only for meaning: `down` errors/removed lines, `up` passing tests/added lines; warnings by shape and weight.
- Strings in English in code, German through gettext (`po/de.po`), VS words in both (*Projektmappen-Explorer*, *Fehlerliste*, *Ausgabe*).
- AI: Ollama on `http://localhost:11434` only, both parts off by default, one "AI off" switch.
- Typing never waits on LSP, build, diagram or AI; LSP replies carry the document version, stale ones dropped.
- Evidence words in every doc: *tested* (how), *built*, *planned*.
- Code, comments, docs in English.

## Review Focus

1. **A `.sln` (not `.slnx`) or a file without BOM / with LF**: opening, editing one line and saving must keep LF/no-BOM; tested in Task 1.1 (`text_file_keeps_lf_without_bom`).
2. **A `.cd` with elements Anvil does not model** (`<Comment>`, `<AssociationLine>` with `<Path>`, `<Lollipop>`, `<Compartments>`): moving one card changes only that `<Position>`; tested in Task 1.4 (`moving_one_card_changes_only_its_position`).
3. **A project path with spaces or non-ASCII** (`Übung 1/`): host commands get it as one argument, the ZIP keeps the name; tested in Task 1.8 (`zip_keeps_unicode_names`) and Task 2.1 (`host_command_quotes_nothing_and_passes_args`).
4. **Broken C# while typing** (missing brace): the structure model still lists the types before the error, the diagram does not drop cards; tested in Task 1.6 (`tolerates_unclosed_class`).
5. **The startup project is not the first project in the solution**: Anvil warns that VS will start the first one; tested in Task 1.2 (`first_project_is_vs_startup`).
